# v1: 実データ連携（Google Calendar 直接同期・読み取り）

## 目的
MuseCal の存在理由そのもの。Android のカレンダー同期が止まっても、Google Calendar API から直接読むことで予定が欠けない状態にする。v0〜v0.3 は同梱サンプルでの見た目検証だったが、v1 で実データに切り替える。

## 範囲（やること）
- Google アカウントでログイン（Google Sign-In / Credential Manager）
- calendarList を取得し、既存のタブ（メイン / AI木曜会 / 日本の祝日）と実際のカレンダーを対応づける
- 表示中ウィンドウ（月表示の6週分）の予定を取得し、既存の描画モデル（帯・文字色・終日/時間指定）に流す
  - 繰り返し予定は singleEvents で展開済みのものを受け取る
  - 色は event の colorId → 既存パレット、カレンダー色は calendarList の backgroundColor を使う
- 更新タイミング： 起動時＋手動リフレッシュ（プル）。取得できない間は前回キャッシュを表示し、古いことを画面で分かるようにする
- トークンは端末内（アカウントマネージャ側）にのみ保持。Muse 側のサーバーは持たない

## 範囲外（やらないこと）
- 予定の作成・編集・削除（書き込みは v2 以降に別途提案）
- 通知・リマインダ、ウィジェット
- Android カレンダープロバイダ経由の読み取り（同期停止の影響を受けるため採らない）

## 方式
- 認証: Google Sign-In（Android OAuth クライアント）。scope は読み取り専用 `calendar.readonly`
- 通信: Calendar API v3 の REST を直接呼ぶ（google-api-client の導入は実装時に判断し、理由を記録）
- 前提（ユーザー側の作業が1つだけある）:
  - Google Cloud プロジェクトを**ユーザーの Google アカウント**で作成し、Calendar API を有効化、OAuth 同意画面を作成、Android クライアントに次を登録する
    - パッケージ名: `jp.hayashida.musecal`
    - 署名 SHA-1（固定デバッグ鍵）: `43:F0:3C:93:CB:A0:DF:75:78:72:7D:85:40:F0:E6:32:0B:F6:F4:76`
  - 署名鍵を固定した（v0.3）ため、この SHA-1 は今後のデバッグビルドで変わらない。将来リリース鍵を作ったら、その SHA-1 を追加登録する
  - 追記（2026-11-21、V1-1 実装で判明）: Credential Manager の GetGoogleIdOption は serverClientId として**「ウェブアプリケーション」タイプの OAuth クライアント ID** を別途要求する。同じ Cloud プロジェクトに Web クライアントも作成し、その ID をアプリの `R.string.google_web_client_id` に設定すること（現在はプレースホルダ）。Android クライアント（パッケージ名＋SHA-1）は AuthorizationClient 側の認可で使われる

## REQUIREMENTS.md への追記案（ユーザーの承認で正本化）
- 新節「データ連携」: 取得元は Google Calendar API（読み取り専用）、対象は calendarList の全カレンダー、表示ウィンドウ分を取得、キャッシュと鮮度表示、未ログイン/取得失敗時はサンプルではなく空＋案内を出す（サンプルと実データの混同を避ける）

## リスク・未決
- OAuth 同意画面が「テスト」状態だと、テストユーザーに登録したアカウントしかログインできない（本人アカウントのみで実用上は問題なし。本公開は審査が要るため当面テスト状態で運用）
- 取得失敗時の見せ方（キャッシュの古さ表示の具体形）は実装時に画面で確認して決める
- 大量の繰り返し予定がある場合の取得量（ウィンドウを絞るため実用範囲と想定）

## V1-4 実装計画（2026-11-22）
- 問題・成功基準: 再起動で予定が消える問題を解消し、同一アカウントのキャッシュを先に表示して表示窓を再取得する。失敗しても保持し、成功した取得の日時を表示する。N1 は破棄後の取得再判定で解消する。
- 範囲: EventWindowStore の snapshot、org.json による内部ストレージ保存、起動・成功時の接続、回帰テスト。オフライン表示に必要なタブも保存する。
- 制約・依存: 既存の認可札・世代判定を維持。トークン保存なし、追加ライブラリ・権限なし。STATUS.md は変更しない。
- 順序: snapshot/保存→アカウント別復元と起動更新→成功日時と N1→単体・check.sh・画像検証→push/CI。
- 未解決: 実機の機内モードと見た目の受理はユーザー、独立レビューは Claude Code が担当。仕様 converge は既存 V1-6。
