# 提案: 繰り返し予定の「すべての予定」編集（2026-11-23、ユーザー「全部進める」）

## 背景
v2（V2-3）で編集は実装したが、繰り返し予定のシリーズ編集は制約として見送った（インスタンス単体の編集のみ可、削除はシリーズ対応済み）。この制約を解消する。

## 決定事項
1. 繰り返しインスタンスの編集画面に、適用範囲の選択（この予定のみ / すべての予定）を追加する。既定は「この予定のみ」（従来動作）。
2. 「すべての予定」ではシリーズのマスター予定（recurringEventId）を対象にする。フィールドはマスターから読み込んで表示し（インスタンスの開始時刻は例外でずれている場合があるため使わない）、保存は GET＋events.update（If-Match の競合検出つき）で未編集フィールドと recurrence を保持する。カレンダー移動はマスターへの events.move とする。
3. 時刻・日付の変更はマスターの開始・終了に適用する（シリーズ全体が API の意味論どおりにずれる）。繰り返しルール（RRULE）そのものの編集、「この予定以降」の分割は対象外。
4. 個別に例外編集されたインスタンスは、シリーズ編集でも上書きしない（API の意味論どおり。制約として仕様に明記する）。
5. 読み取り専用カレンダーは従来どおり編集不可。マスターの取得に失敗した場合は何も書かずにエラー表示する。
6. 収束（SE-2）で REQUIREMENTS §8.1 の制約記述を更新し、QC に実機確認項目（シリーズ編集の反映）を追加する。実機確認はユーザー側の QC として未確認のまま残る。
